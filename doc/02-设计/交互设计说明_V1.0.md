## 1. 控件体系交互

### 1.1 Widget控件模型

平台采用Widget（控件）化的交互模型。AI对话返回的交互卡片（InteractiveCard）对应不同的Widget控件类型，用户可以在聊天面板中预览卡片摘要，点击后展开为完整可操作的控件。

**控件类型与交互映射：**

| 控件类型 | 卡片预览形态 | 展开后的完整控件 | 支持的操作 |
|---------|-------------|----------------|----------|
| task_list | 任务摘要列表 | 完整任务列表/看板双视图 | 改状态、改优先级、查看详情 |
| kanban | 分栏看板缩略图 | 拖拽式看板 | 拖拽改状态、快速编辑 |
| progress | 进度条预览 | 柱状进度图表 | 查看详情、导出 |
| table | 表格缩略 | 完整可操作表格 | 排序、筛选、行操作 |
| chart | 图表缩略 | 完整交互图表 | hover查看数值、切换图表类型 |
| file | 文件信息卡 | 文件预览/下载 | 下载、版本管理 |
| report | 报告摘要 | 完整报告 | 展开章节、导出 |

### 1.2 卡片预览交互

聊天消息中的卡片呈现为紧凑的预览形态：

1. **展示规则**：每条AI回复最多展示3张卡片，按重要性排序
2. **点击行为**：用户点击卡片区域，卡片展开为完整控件视图（在侧边栏或页面内展开）
3. **Action按钮**：每张卡片底部包含2-4个快捷操作按钮（如"查看详情"/"导出报告"），点击按钮直接触发对应操作或发送新的对话消息

### 1.3 控件内操作

展开后的控件支持直接操作，操作结果通过API持久化：

- **任务状态变更**：在任务列表或看板中点击状态标签，选择新状态，调用 `PATCH /api/tasks/{id}` 更新
- **优先级变更**：点击优先级标签切换 high/medium/low
- **看板拖拽**：从一个状态列拖拽到另一个状态列，触发状态更新
- **表格排序/筛选**：点击列头排序，使用筛选器过滤数据

## 2. 页面交互

### 2.1 全局导航

**侧边栏导航结构：**

```
首页（/）
我的工作（/tasks）
我的日常（/daily）
├── [更多] 可折叠分组
│   ├── 人事管理（/hr）
│   ├── 财务管理（/finance）
│   └── 知识库（/knowledge）
├── [AI] 可折叠分组
│   └── AI小助理（/chat）
├── [收藏] 可折叠分组
│   └── （空态提示）
└── [工作区]
    ├── 主工作区（可折叠/展开）
    │   ├── 项目总览（/projects）
    │   └── 各项目看板（/projects/{id}）
    └── 设置（/settings）
```

**导航交互规则：**

1. **当前页高亮**：使用 `NavLink` 的 `isActive` 判断，激活项显示蓝色背景 `bg-[#cce5ff]` 和蓝色文字 `text-[#0073ea]`
2. **分组折叠**：可折叠分组默认状态不同 — "更多"默认折叠，"AI"默认展开，"收藏"默认折叠
3. **工作区折叠**：主工作区可通过下拉箭头切换展开/折叠
4. **项目看板列表**：侧边栏底部区域显示所有项目，左侧3px色条标识项目状态颜色

### 2.2 顶栏交互

| 元素 | 交互 |
|------|------|
| Logo | 品牌标识，不可点击 |
| 搜索框 | 点击聚焦，支持 `/` 快捷键（UI预留） |
| AI助手图标 | 点击跳转到 `/chat` 页面，激活状态蓝色高亮 |
| 通知铃铛 | 点击打开/关闭通知面板，显示未读数量红色圆点 |
| 用户头像 | 点击展示用户信息（预留） |

### 2.3 页面标题栏

内容区顶部11px高度的标题栏，动态显示当前页面标题：

- 导航页面：显示对应的中文标签（首页/我的工作/人事管理等）
- 项目详情页：显示项目名称（从projectStore获取）
- 未匹配路由：显示"牛油果CoWork"

### 2.4 Tab标签页

项目详情页等页面使用Tab标签切换不同视图：

- 点击Tab标签切换内容区
- 当前Tab底部蓝色指示条
- Tab切换不刷新页面，仅切换内容组件

## 3. AI聊天交互

### 3.1 聊天面板结构

AI聊天面板（AIChatPanel）位于页面右侧，宽度380px：

```
+-- AI面板头部 --------------------------+
|  [牛油果吉祥物] AI智能助手              |
|  ✨ 当前页面上下文         [新对话] [关闭]|
+------------------------------------------+
|  [项目上下文横幅]（仅项目详情页显示）      |
+------------------------------------------+
|                                          |
|  消息区域（滚动）                         |
|  - 用户消息（右对齐）                     |
|  - AI回复（左对齐 + 卡片）               |
|  - 打字指示器                            |
|                                          |
+------------------------------------------+
|  [查看进度] [风险分析] [本周任务] [生成周报]|
+------------------------------------------+
|  输入框 + 发送按钮                        |
+------------------------------------------+
```

### 3.2 上下文感知

AI面板会根据用户当前所在页面动态调整行为：

**页面上下文标签：**

| 页面路径 | 显示标签 |
|---------|---------|
| `/` | 首页仪表盘 |
| `/projects` | 项目管理 |
| `/projects/{id}` | 项目: {项目名称} |
| `/knowledge` | 知识库 |
| `/hr` | 人事管理 |
| `/finance` | 财务管理 |
| `/tasks` | 任务工作台 |

**快捷建议动态切换：**

不同页面显示不同的快捷建议标签组：

- **首页**：查看进度、风险分析、本周任务、生成周报
- **项目列表**：对比项目进度、找出风险项目、项目统计、生成汇报
- **项目详情**：分析此项目、任务建议、风险评估、生成进度报告（注入项目名称）
- **人事管理**：员工概况、考勤分析、待审假单、薪资汇总
- **财务管理**：财务概览、待审报销、预算执行、逾期发票
- **任务工作台**：我的任务、逾期任务、高优先级、任务统计
- **知识库**：搜索文档、最近更新、常用模板、知识问答

### 3.3 消息发送流程

```
用户输入文字 → 点击发送/按回车
  │
  ├── [项目详情页] 自动注入项目上下文前缀: "[关于项目: xxx] 用户消息"
  │
  ├── 显示用户消息气泡（右对齐）
  ├── 显示AI思考指示器（跳动圆点）
  │
  ├── 调用 POST /api/chat/stream（SSE流式）
  │   ├── 接收 token 事件 → 逐字渲染AI回复（左对齐气泡）
  │   └── 接收 done 事件 → 渲染交互卡片
  │
  └── 隐藏思考指示器
```

### 3.4 流式消息渲染

1. **思考状态**：当 `isLoading=true` 且无流式消息时，显示TypingIndicator（三个跳动圆点）
2. **流式输出**：token逐个到达，实时追加到当前AI消息气泡中（`isStreaming`标记）
3. **卡片渲染**：`done`事件到达后，在消息底部渲染InteractiveCard卡片组
4. **自动滚动**：新消息到达时自动滚动到底部（smooth滚动）

### 3.5 快捷建议交互

- 底部标签组显示4个快捷建议按钮
- 点击按钮直接发送对应的预设消息
- 加载中时按钮禁用（`disabled:opacity-45 disabled:cursor-not-allowed`）
- 标签样式：圆形胶囊形状，hover时蓝色强调

### 3.6 新对话

点击面板头部的"新对话"按钮（PenSquare图标）：
- 清空所有历史消息
- 重置对话上下文
- 加载中时按钮禁用

## 4. 表单交互

### 4.1 Drawer抽屉模式

平台中的创建和编辑操作采用Drawer（抽屉）模式：

- 从页面右侧滑入
- 半透明遮罩层覆盖背景
- 表单内容置于抽屉中
- 点击遮罩层或关闭按钮收起抽屉

### 4.2 任务创建

通过多个入口可以创建新任务：

1. **任务工作台**：点击"新建任务"按钮
2. **项目详情页**：在任务列表区域点击添加按钮
3. **AI对话**：AI回复中的action按钮（如"分配任务"）

**创建任务表单字段：**

| 字段 | 控件 | 必填 | 说明 |
|------|------|------|------|
| 任务名称 | 文本输入 | 是 | 1-256字符 |
| 负责人 | 下拉选择 | 否 | 团队成员列表 |
| 优先级 | 下拉选择 | 否 | 高/中/低，默认中 |
| 截止日期 | 日期选择器 | 否 | 日历选择 |
| 描述 | 多行文本 | 否 | 任务详细描述 |

### 4.3 表单校验

- 前端使用 Pydantic 模型对应的字段校验规则
- 必填字段为空时显示红色提示
- 数值字段校验范围（如金额 > 0）
- 提交按钮在校验不通过时禁用

### 4.4 任务详情弹窗

点击任务列表中的任务项，弹出 TaskDetailModal：
- 显示任务完整信息
- 支持内联编辑字段
- 修改后实时调用PATCH接口保存

## 5. 通知交互

### 5.1 通知面板（NotificationPanel）

**触发方式：** 点击顶栏通知铃铛图标

**面板行为：**

1. 面板从铃铛图标下方绝对定位弹出
2. 点击面板外区域自动关闭（mousedown outside检测）
3. 面板固定宽度320px，最大高度384px，超出部分滚动

**通知列表交互：**

| 操作 | 交互 |
|------|------|
| 点击通知项 | 标记该通知为已读 |
| hover显示删除按钮 | 右侧出现X图标（opacity-0 -> opacity-100） |
| 点击X按钮 | 删除该通知（阻止冒泡） |
| 点击"全部已读" | 标记所有通知为已读 |
| 点击"关闭" | 关闭面板 |

**通知项视觉状态：**

| 状态 | 样式 |
|------|------|
| 未读 | 浅蓝色背景 `bg-primary/[0.03]`，左侧蓝色小圆点 |
| 已读 | 透明背景，hover时显示 `bg-[#f6f7fb]` |

**通知类型图标：**

| 类型 | 图标 | 颜色 |
|------|------|------|
| success | CheckCircle2 | `text-success bg-success/10` |
| warning | AlertTriangle | `text-warning bg-warning/10` |
| info | Info | `text-info bg-info/10` |
| error | XCircle | `text-danger bg-danger/10` |

**空态：** 当无通知时，显示铃铛图标 + "暂无通知"文字

### 5.2 Toast通知（NotificationToast）

Toast通知用于操作反馈，全局浮动在页面底部或右上角：

- 自动出现，持续数秒后自动消失
- 不阻断用户操作
- 支持多条Toast叠加显示
- 通过 `notificationStore` 全局管理

### 5.3 未读计数

- 顶栏铃铛图标右上角显示红色圆形未读数字
- 数字为0时隐藏
- 样式：`bg-danger text-white text-[10px] font-bold rounded-full`

### 5.4 时间显示

通知时间使用相对时间格式：

| 时间差 | 显示 |
|--------|------|
| < 60秒 | 刚刚 |
| < 60分钟 | X分钟前 |
| < 24小时 | X小时前 |
| < 7天 | X天前 |
| >= 7天 | MM月DD日 |

## 6. 数据操作交互

### 6.1 CRUD操作反馈

| 操作 | 交互反馈 |
|------|---------|
| 创建成功 | Toast提示"创建成功"，列表自动刷新 |
| 更新成功 | Toast提示"更新成功"，数据即时更新 |
| 删除操作 | 确认弹窗 → 确认后执行删除 → Toast提示 |
| 操作失败 | Toast错误提示，显示错误信息 |

### 6.2 乐观更新

部分操作采用乐观更新策略：

1. 用户执行操作后，前端立即更新UI状态
2. 同时发送API请求到后端
3. 如果API失败，回滚UI状态并显示错误提示

### 6.3 列表操作

| 交互 | 说明 |
|------|------|
| 状态筛选 | 下拉菜单筛选，前端过滤或发送API参数 |
| 搜索过滤 | 输入框实时过滤（前端本地） |
| 排序 | 点击表头切换升序/降序 |
| 分页 | 前端分页（数据量较小时） |

### 6.4 项目阶段推进

在项目详情页中，项目阶段推进是一个关键交互：

1. 用户点击"推进阶段"按钮或通过AI对话触发
2. 显示当前阶段和可用的下一阶段选项
3. 用户选择目标阶段
4. 调用 `POST /api/projects/{id}/transition`
5. 后端校验转换合法性
6. 成功：更新阶段标签，记录活动日志
7. 失败：显示错误信息（如"无法从施工跳转到立项"）
