## 1. 测试目标与原则

### 1.1 测试目标
本计划旨在构建一套全面验证 GC TeamWork AI原生协作平台开发的完成度、质量、性能、及合规要求可落地的测试方案。针对平台"对话即操作"的创新交互范式、中国化工程管控要求（招投标、四大财评过程、监理）、私有化大模型Agent架构等核心特点做针对性测试设计。

### 1.2 测试角色分工机制
在当前开发交付模式下，团队将遵循以下清晰责任划分：
- **Claude Code（开发交付方）**：负责项目的前后端代码与架构的实现落地、Agent Prompt调优、集成底层大语言模型等研发活动，并在本地完成基础代码单元测试与自测修改。
- **本机AI助手（测试验证方）**：负责制定系统级与端到端测试用例，执行系统测试验证，对模型调用生成结果及系统页面交互展开全方位黑盒/灰盒验证，追踪和管理缺陷。

## 2. 测试策略与方法 (Testing Strategy)

根据产品的五层系统架构和敏捷交付特性，测试将采取"分层+分阶段"结合策略：

| 测试类型 | 测试对象 | 测试方法/工具 | 责任方 |
|---------|---------|-------------|---------|
| **单元测试 (Unit)** | 前端独立组件 / 后端FastAPI独立路由接口 | Pytest / Jest 等自动化脚本框架 | 开发侧完成 |
| **Agent能力测试** | DispatchAgent意图识别、8大专业Agent | 典型Prompt集跑测，评估输出结构合法性和准确率、模型降级(TaskComplexity)策略 | 测试侧主导 |
| **UI与交互测试** | 可交互卡片体系(InteractiveCard)、抽屉表单(Drawer)、工作台、主题切换 | 按照《各页面及UI设计标准》比对验证、人工黑盒探索 | 测试侧主导 |
| **端到端测试 (E2E)**| 招投标、全生命周期作业流水线(可研->归档)、事件驱动审批预警联动 | 完整业务全链路流转跟踪测试 | 测试侧主导 |
| **性能测试** | 意图解析请求并发、知识库检索响应效率 | Jmeter / 压测数据包 (验证复杂解析<15s, 快速问答<3s) | 测试协办 |
| **安全合规验证** | 越权访问控制(RBAC/ABAC)、数据清洗与金额信息脱敏掩码检测 | 构造非法请求、脱敏规则绕过演练 | 测试侧主导 |

## 3. 测试功能模块划分 (Functional Scope)

针对平台特性，梳理出以下核心测试点，供后续生成具体的 Test Cases：

### 3.1 交互体验层验证 (UI & UX)
- **多模态与消息聊天交互**: 
  - AI聊天界面的流式输出（SSE是否平滑无卡顿现象、打字跳动状态）。
  - 右侧380px对话窗收折时的阻尼与页面重绘情况。根据用户当前停留路由（如首页、任务台），自动注入上下文的体验测试。
- **可交互卡片控件**:
  - 数据卡片(DataCard)、图表卡片(ChartCard)等类型卡片的回显数据排版及点击动作有效性。
  - 任务项控件的乐观锁与操作响应时间测试（如果后端返回异常，状态是否正常回滚）。
- **系统主题样式**: 
  - 正常读取 `themeStore` 进行深色(`dark`)/浅色主题秒级切换和本地持久化。色彩是否符合Monday.com UI规范集及品牌色（如#00c875、#0073ea）。

### 3.2 意图路由与Agent智能体群组验证(Agent Skills)
基于DeepSeek模型/Agent链架构，黑盒验证意图分发精准率。

- **调度大脑 (DispatchAgent)**:
  - **准确率**: 输入含多重指令（"查账并建个计划"），测试生成的JSON数据（`primary_agent`, `secondary_agents` 等）准确性是否符合预期。
  - **多体协同**: 测试多目标工作安排下，各专业Agent并行和串行是否按照《系统架构文档设计》进行流转反馈。
- **特定专业Agent节点验证**:
  - **项目管理Agent**: 对模糊事项分解为标准WBS树状结构的有效性。
  - **法务/审计 Agent**: 投喂掺杂漏洞字眼的合同文本或高风险的投标报价单，验证标注异常和废标风险的能力。
  - **过控 Agent (核心预警)**: 超越进度及开销基线时，验证自动化等级触发预警模型(黄、橙、红)是否向对应的相关责任人员送达。

### 3.3 国家工程标准业务全链路验证
确保满足国内财评与工程流程控制的标准刚需：

- **典型场景一大连通**: 可研创建 -> 虚拟招投标生成 -> 合同模拟签署与复查验 -> 四阶段验证评估（概预结决）。
- **场景二：过程变更控制 (联动反应)**: 前端提交某个工程材料的临时变更申请表 -> （触发）材料过控风险评估 -> 触发财务预算重新预估 -> 法务审批评估 -> 生成最后《变更审批表》。从前置到闭环测试各个微服务模块。

### 3.4 Dashboard管理者全景视图 (Visualizations)
- **多项目群态势大盘**: 数据刷新周期小于 5 分钟要求。坐标散点图、风险雷达分布是否与后台基础数据联动拉通。
- **全局思维导图展现**: mind-map形式的组件展开折叠顺滑度，红绿色标的一致性呈现。
- **权限与隔离机制穿透校验**: 用各类角色的模拟账号越看平级数据、上级看板，保证不出现严重的未授权信息泄漏。

## 4. 阶段测试里程碑与通过标准 (Milestones & Exit Criteria)

建议测试将分步骤同步融入开发交付周期(P0~P4)：

| 里程碑时期 | 测试核心重点 | 通过准则基线 (Exit Criteria) |
|-----------|---------|-----------------------|
| **P0: 架构与基座** | Agent意图路由系统畅通性，基础UI（如表格、看板视图）呈现与流式交互响应。 | Agent准确调用返回正常结构数据；前端多视图无白屏及卡顿报错。 |
| **P1, P2: 业务模块** | 四大控制管理全周期流程链是否贯通；专业Agent技能测试和打分微调。 | P0级/P1级系统主流程阻塞缺陷被清零。核心流场景通过率100%。 |
| **P3: 高级全景看板** | 各项统筹性能图表数据汇聚查询；规则化触发自动推行功能测试测试引擎动作。 | 图表拉取展现延迟稳定低线；触发预警漏报率≤1%。 |
| **P4与验收预演(UAT)**| 向量检索性能(Million Data)压测、数据安全审计模拟脱敏渗透测试、灰盒验收。 | 根据项目管理要求，修复所有遗留重度风险问题并归档记录完备。 |

## 5. 后续开展协作说明

为了更好地实施自动化/手动的测试配合：
1. **测试用例数据集构筑计划**: 本次计划明确后，作为测试负责方，我将优先组织编写并建立一份详实复杂的 `Agent模拟对话指令库集` 作为我们的首批弹药库，专门针对那些语言歧义高、业务多并发的语料，提前部署防御测试。
2. **前后端解耦联调Mock**: 推荐开发方在完成后端API时严格按照设计文档的标准JSON暴露，本方案能够使用人工Mock数据源前置展开自动化脚本。
3. **缺陷溯源体系**: 验证测试过程中若触发Bug异常，本人将生成详尽排查指引与上下文快照（复现前置操作+期望结果+网络抓取/堆栈日志信息）提交至Claude Code进行复查，加速研发循环并核查其复现消除结果。
